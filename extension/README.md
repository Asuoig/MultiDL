# MultiDL 浏览器集成扩展

把浏览器（Chrome / Edge）的下载交给本地的 MultiDL 客户端。

> **这是可选功能。** 不装扩展也能用 MultiDL.exe 手动下载；装了只是让浏览器里的下载自动转过去。

---

## 前置条件

先启动 **MultiDL.exe**（它默认在 `127.0.0.1:8765` 开一个本地 API）。
扩展只有在客户端运行时才生效；客户端没开，扩展会自动放行，浏览器照常原生下载。

---

## 安装（Chrome / Edge）

1. 启动 `MultiDL.exe`。
2. 地址栏打开 `chrome://extensions`（Edge 是 `edge://extensions`）。
3. 右上角打开「**开发者模式**」。
4. 点「**加载已解压的扩展程序**」。
5. 选择本 `extension` 文件夹（就是包含 `manifest.json` 的那一层）。

装好后浏览器工具栏会出现 MultiDL 图标，点开应显示「已连接」。

> Chrome 会提示「该扩展程序未列在 Chrome 应用商店中」或「请停用以开发者模式运行的扩展程序」。
> 这是 Chrome 对**所有非商店扩展**的统一安全提示，不是本扩展有问题。
> 选「保留」/「启用」即可；Chrome 启动时若弹「停用开发者模式扩展」，点忽略/保留。

---

## 工作方式

- 监听 `chrome.downloads.onCreated`；
- 发现新下载 → `POST http://127.0.0.1:8765/api/tasks` 把 URL 交给客户端；
- **只有客户端确认接单后**才取消浏览器原生下载；
- 客户端没开 → 接口失败 → 不取消，浏览器自己下（不会吞文件）。

右键菜单还提供「用 MultiDL 下载此链接 / 当前页面」。

---

## 验证是否生效

1. 保证 `MultiDL.exe` 在运行（任务栏/托盘有图标）。
2. 点扩展图标，顶部应显示绿点「已连接」；显示「未连接」就说明客户端没开或端口不一致。
3. 在浏览器里点任意一个大文件下载。
4. 浏览器原生下载应被取消，同时 MultiDL 客户端里出现该任务并开始下载。

---

## 接管失败怎么办

v1.0.21 起，接管失败会**明确告诉你**：扩展图标出现红色「!」角标 + 系统通知，
点开扩展图标能看到具体原因（存在 `lastError` 里）。

按提示排查，90% 是下面三种：

| 现象 | 原因 | 处理 |
|---|---|---|
| 通知「连不上本地服务」/ 图标「未连接」 | **客户端没启动**（最常见） | 双击桌面 `MultiDL.exe`，等托盘图标出现再试 |
| 通知「本地服务拒绝（403）」 | 客户端与扩展版本不一致 | 两边都更新到同一版本（客户端 exe + 扩展 zip 一起换） |
| 一直「未连接」但客户端在跑 | 端口不一致，或被别的程序占了 8765 | 在扩展 popup 里把端口改成客户端实际端口；或看客户端日志 `%LOCALAPPDATA%\MultiDL\logs\multidl.log` |

排查客户端侧：`选项 → 打开日志文件夹`，搜 `API 拒绝`，会记下被拒请求的
`Origin` / `Host` / `User-Agent`，可直接判断是来源校验还是别的原因。

---

## 卸载

`chrome://extensions` → 找到「MultiDL 集成」→ 移除。不影响客户端本体。

---

## 说明

本扩展只用浏览器公开的 `downloads` API，不注入页面脚本、不读网页内容、不上传任何数据；
所有通信只发生在你本机的 `127.0.0.1`。
